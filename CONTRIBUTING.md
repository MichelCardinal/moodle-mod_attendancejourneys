# Contributing to Attendance Journeys

Report reproducible issues through this repository's Issues tab. Use fictional participants and remove names, email addresses, grades, session tokens and private comments from screenshots and logs. Do not attach Moodle configuration files or backups with user data.

Before proposing a change, describe its pedagogical effect. Preserve the rule that a journey result remains provisional until explicit closure, independent journey thresholds, original attendance history and Moodle grade protections. New features should be discussed before implementation.

Follow Moodle coding standards, write code and comments in English, and use Moodle APIs for permissions, forms, database access, privacy and backup/restore. Keep English language strings in lang/en; contribute translations through AMOS after component approval.

Add meaningful regression coverage when behavior changes. Run moodle-plugin-ci checks and relevant PHPUnit tests against supported Moodle branches. Explain validation and remaining limits in the pull request. Contributions must be compatible with GPL v3 or later; retain original copyright and licence notices.
